# Prompt: Одностраничный сайт‑визитка для художника Dinburgh

Ты — AI‑агент (Senior Frontend Engineer + Web Designer). Разработай **одностраничный сайт‑визитку** для художника с никнеймом **Dinburgh**.

Цель: современный, темный, минималистичный сайт с плавными анимациями, “стеклянными” элементами в духе **Liquid Glass iOS 26**, и удобной системой ручного добавления работ в портфолио через структуру папок.

---

## 1) Визуальный стиль (обязательные требования)

### Базовая тема
- Основной фон: **черный + оттенки серого**, общая тональность — “темная”.
- Основной текст: **чаще белый** (там, где не нарушает контраст).

### Акцентная палитра (использовать точечно, не “засвечивать” сайт)
- `#FFFFDC` (теплый светлый)
- `#FF4500` (яркий оранжево‑красный)
- `#440300` (темно‑бордовый)

Использование: акценты на hover/active, линии/подчеркивания, небольшие UI‑сигналы, микро‑градиенты в стекле, маркеры выбранного таба.

### “Стеклянный” стиль (Liquid Glass)
Для кнопок/карточек/панелей:
- Полупрозрачность + blur (`backdrop-filter`)
- Тонкая светлая обводка (1px, низкая непрозрачность)
- Мягкий световой блик/градиент сверху
- Тени деликатные, без “пластика”
- На hover: чуть больше яркости/контраста, легкий “подъём” (translate/scale) и изменение блика

---

## 2) Макет и структура страницы (одна страница)

Используй **предоставленный прототип от руки** как источник компоновки и визуальной иерархии. Важнее всего — порядок блоков и их смысл.

### 2.1 Header (фиксированный)
- Всегда сверху (sticky/fixed).
- Содержит только имя/логотип текстом: `dinburgh` (в нижнем регистре).
- При прокрутке: слегка меняет фон (чуть плотнее стекло/blur), чтобы читался на любом фоне.

### 2.2 Блок Bio (сразу под header)
- Короткий текст о художнике.
- Оформление: стеклянная панель/карточка.
- Небольшая анимация появления при загрузке (fade/slide).

### 2.3 Блок Portfolio (ниже Bio)
- Есть **3 подраздела** (табы/переключатели).
- По умолчанию открыт **самый левый** подраздел.
- Переключение табов: плавная анимация (подчеркивание/ползунок/индикатор + fade контента).
- Внутри таба: **сетка карточек работ**.

---

## 3) Карточка работы и просмотр (ключевой UX)

### Карточка работы (в сетке)
- Показывает превью изображения.
- Hover (desktop): появляется название работы (оверлей/подпись) с легким затемнением изображения.
- Нажатие (click/tap): открывает **просмотр на этой же странице** поверх контента.

### Просмотр работы (modal / lightbox)
- Затемнение фона + “почти на весь экран” карточка/панель со стеклянным стилем.
- Внутри:
  - большое изображение (адаптивно по экрану)
  - название
  - текстовое описание
- Закрытие: кнопка ✕ + клик по подложке + Esc.
- Анимации: плавный zoom/fade при открытии/закрытии.
- Важно: корректная работа на мобильных (скролл внутри модалки, блокировка фона).

---

## 4) Контент‑менеджмент через папки (обязательное требование)

Нужно, чтобы я мог **вручную добавлять** работы, создавая папки с ассетами и описанием — без правок кода.

### 4.1 Структура контента
Сделай систему, которая автоматически сканирует/подхватывает работы из структуры вида:

```
/content/portfolio/
  01-digital/
    work-slug-1/
      image.(jpg|png|webp)
      meta.(json|md)
    work-slug-2/
      ...
  02-painting/
    ...
  03-fashion/
    ...
```

- Внутри каждой папки работы:
  - 1 изображение (основное превью/основное для модалки)
  - файл описания `meta` с **title** и **description** (минимум)

### 4.2 Формат meta (выбери один и задокументируй)
**Вариант A — `meta.json`:**
```json
{
  "title": "Название работы",
  "description": "Описание работы в 1–5 предложениях."
}
```

**Вариант B — `meta.md` с frontmatter:**
- `title`
- `description` (или первый абзац как описание)

**Требование:** агент должен реализовать парсер и сбор данных так, чтобы добавление новой папки автоматически добавляло карточку в нужный таб.

## 5) Технические требования

Выбери стек, который удобен для статического деплоя и анимаций. Рекомендация:
- **React + TypeScript + Vite**
- TailwindCSS (или CSS modules) для стилей
- Framer Motion (или аналог) для анимаций
- Сборка должна быть воспроизводимой, проект — аккуратно структурированным.

### Производительность и качество
- Оптимизация изображений (webp где возможно, адекватные размеры, lazy-load).
- Lighthouse‑дружелюбно: не перегружать тяжелыми эффектами, blur — умеренно.
- Доступность: фокус‑стили, Esc закрывает модалку, aria‑атрибуты где нужно.
- Адаптивность: мобильный/планшет/desktop.

---

## 6) Definition of Done (DoD)

1) Одностраничный сайт с фиксированным header, блоками Bio и Portfolio.  
2) Три таба портфолио, левый открыт по умолчанию, переключение анимировано.  
3) Карточки работ с hover‑названием и модальным просмотром (изображение + title + description).  
4) Контент добавляется через папки в `/content/portfolio/...` без правки кода.  
5) Темная тема + точечные акценты заданной палитры + glass‑стиль “Liquid Glass”.  
6) Проект собран, запускается локально, есть короткий `README` как добавлять работы.
